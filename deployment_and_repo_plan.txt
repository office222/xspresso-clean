Suggested Branching Strategy:
- main: stable release branch
- develop: current working build
- feature/*: temporary feature branches

Suggested Versioning:
- v0.x = early internal prototypes
- v1.0 = first public launchable version
- v2.0 = advanced copy, cloning, and video production features

Suggested Build Order:
1. Lock V1 scope
2. Finalize credits and monitoring rules
3. Finish onboarding and campaign generation flow
4. Finish dashboard and alert flow
5. Connect billing and usage tracking
6. Prepare release checklist
7. Final QA pass
8. Launch

Suggested Sync Targets:
- GitHub for source control and branch history
- Google Drive for shared docs and copy references
- Local working folder for active editing

Guiding Principle:
Keep the product simple enough to ship, but structured enough to grow.
